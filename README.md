# 知识问答 Agent

一个基于自有知识库作答、且**每条结论都能追溯到原文位置**的问答应用。

核心约束只有两条：

1. **只答知识库里有的**——检索不到依据就直接说「没查到」，不调用模型，不靠模型记忆兜底。
2. **每句话都要有出处**——回答里的每个事实性陈述都带 `[n]` 引用标记，点开即可看到文档名、行号区间和原文高亮。

## 特性

- **双闸校验**：检索层先判定有无依据；模型生成后再校验引用标记，答案里没有任何有效引用 → 判定为没查到，直接丢弃。
- **精确原文定位**：切片同时记录字符偏移与行号，前端可跳到原文并高亮对应行。
- **零依赖**：只用 Node.js 标准库，无 npm 依赖，克隆即可运行。
- **知识库自带**：支持粘贴文本或上传 `.md` / `.txt`，同篇重复添加即更新。
- **模型无关**：任何 OpenAI 兼容接口（DeepSeek / 通义 / 智谱 / Kimi / OpenAI）都能接。
- **诚实降级**：未配置模型时不做假装，明确标注「原文摘录模式」，只展示原文片段。

## 快速开始

```bash
node server.js          # 或 npm start
# 打开 http://localhost:3000
```

首次启动会自动从 `data/seed/` 载入示例知识库（一套虚构产品的帮助文档），方便直接体验。
删掉 `data/kb.json` 即可重新载入示例。

## 配置大模型

**方式一：环境变量（推荐，全站生效）**

```bash
cp .env.example .env
# 填入 LLM_API_KEY
```

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `LLM_BASE_URL` | OpenAI 兼容接口地址 | `https://api.deepseek.com/v1` |
| `LLM_MODEL` | 模型名 | `deepseek-chat` |
| `LLM_API_KEY` | 密钥 | 空 |
| `PORT` | 监听端口 | `3000` |

**方式二：页面内配置**
点右上角「模型设置」，填入地址、模型名和 Key。配置仅存在访问者本机浏览器，经服务转发调用，服务端不落盘、不写日志。

两种都没配时，应用自动进入「原文摘录模式」，仍然给出可定位的原文片段。

## 工作原理

```
问题
 ├─ 分词（中文 bigram）+ BM25 粗排
 ├─ 字符级覆盖复核  ← 问句里的跨词假 bigram 不参与判定，避免误判「没查到」
 ├─ 依据判定：覆盖率 < 0.34 → 直接返回「没查到」，不调用模型
 ├─ 受约束生成：只喂片段，要求每句带 [n]，资料不足只许输出 INSUFFICIENT
 └─ 引用校验：[n] 越界剔除；一条有效引用都没有 → 判定为没查到，丢弃答案
```

「有没有依据」的判定用**字符级覆盖**而不是 BM25 分数：口语问「多少钱一个月」和原文「价格」没有共同 bigram，任何基于词的阈值都会判成没查到。字符覆盖能识别「价格」这段连续字符出现在原文里。

## 目录结构

```
server.js            零依赖 HTTP 服务：静态资源 + API
lib/tokenize.js      中文 bigram / 英文分词
lib/chunker.js       切片，记录 charStart/charEnd 与 startLine/endLine
lib/store.js         知识库存储（data/kb.json），含示例库自动装载
lib/retrieval.js     BM25 + 字符覆盖 + 依据判定
lib/llm.js           OpenAI 兼容调用
lib/agent.js         问答编排：判定 → 生成 → 引用校验
public/              前端（原生 JS，无构建）
data/seed/           示例知识库
```

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/ask` | `{question, topK?, llm?}` → 答案与引用 |
| `GET` | `/api/docs` | 文档列表 |
| `POST` | `/api/docs` | `{name, content}` 新增或覆盖 |
| `GET` | `/api/docs/:id` | 文档全文与切片位置 |
| `DELETE` | `/api/docs/:id` | 删除文档 |
| `GET` | `/api/stats` | 知识库与模型状态 |
| `POST` | `/api/config/test` | 测试模型连通性 |

`/api/ask` 返回的 `mode` 有四种：`llm`（模型作答）、`excerpt`（原文摘录）、`insufficient`（没查到）、`error`（模型调用失败）。

## 已知局限

- 检索是关键词 + 字符覆盖，不做语义向量检索。问法和原文用词完全对不上（例如问「怎么便宜点」而原文只有「折扣」）时，会按设计返回「没查到」而不是猜测。
- 知识库存在单个 JSON 文件里，适合单实例、中小规模文档（数百篇量级）。上万篇建议换成向量库。
- 切片按段落聚合，跨段落的推理需要模型自己串联多条引用。
